## 1. 范围与排序

### Phase A · 安全与数据底线（后端，先做）

**F13 凭证边界**（P2 → 建议 M4 首项）
- **现状**：MCP server 的 `env` 明文存 DB，`McpToolProvider` 拉取后注入工具执行环境；Worker 回合同样拿到完整凭证，无边界。
- **对标**：行业收敛到「凭证留主进程，Worker 不注入环境变量」+ daemon token 可吊销 + OAuth 委托；单机场景可极简。
- **做法**：
  1. 凭证值从 `mcp_servers.env` 的明文列迁到**独立 `secrets` 表**（值加密存储，主密钥留主进程内存）
  2. 工具执行时凭证仅经**主进程代理**注入（`McpToolProvider` 持锁引用，不落入 Worker 上下文/日志）
  3. `env` 入参摘要化：`args_digest` 对含 key/token 的键打码
- **验收**：DB dump 无明文凭证；Worker 工具日志无凭证明文；重启后凭主密钥恢复可用。
- **落点**：`mcp/manager.rs`、`mcp/tool_provider.rs`、`agent/tools/*`、`storage/`（新增 secrets 表）、`args_digest`。

**F10 并行隔离/变更集**（P2，PRD §9 标注数据损坏风险）
- **现状**：多 Worker 并发写同 workspace，`resolve_fs_path` 只防越界不防互相覆盖。
- **对标**：git worktree 隔离 + 延迟到显式合并点（Cursor 2.0 / Claude Code `isolation: workspace`）。
- **做法（单机极简）**：
  1. 任务卡声明**输出文件范围**（`output_spec` 已有字段 → 补默认约束）
  2. Worker 写前经 `workspace` 端口登记「意向写入」；同文件被并发声明 → 冲突通知群主（不必分布式锁）
  3. **变更集**：每次工具写盘记录 `(file, worker, run_id, before_hash, after_hash, ts)` 到 `changeset` 表
  4. IX-10 消费该表做「本次变更集」汇总 + 一键回滚（before_hash 恢复）
- **验收**：两个 Worker 写同一文件 → 第二个被拦并通知；群任务结束给「改了哪些文件/谁改的/可回滚」。
- **落点**：`agent/ports.rs`（Workspace 端口扩展）、`agent/tools/filesystem.rs`、`group/task_board_repo.rs`（output_spec 约束）、新增 `changeset` 表 + repo。

### Phase B · 记忆与知识（后端，可并行）

**F14 记忆分层**（P2）
- **现状**：memory 工具是平的，无分层、无蒸馏、无退役清理。
- **对标**：ReMe 三层（working / core / long-term）+ auto_dream 定时蒸馏 + 退役 cleanup + 知识提案审批。
- **做法（单机口径）**：
  1. 会话记忆表加 `tier`（ephemeral / project / global），`build_history` 按 tier 注入
  2. 定时蒸馏：ephemeral → project 摘要合并（复用 compaction 既有能力），project 过旧条目标 retired
  3. 全局搜索：`memory_search` 命令跨 tier 检索
- **验收**：多轮后会话注入只含当前 tier；蒸馏任务产出摘要；退役条目可查不注入。
- **落点**：`agent/compaction.rs`（复用）、`agent/memory*.rs`（或 session 表扩展）、`commands/memory.rs`。

**F9 Playbook**（P2）
- **现状**：无。
- **对标**：Devin 双资产 —— Playbook（可复用步骤 + 成功标准 + 护栏，Past runs 可参考）+ Knowledge（按 trigger 条件注入）。
- **做法（单机极简）**：
  1. `playbooks` 表：name / steps(JSON) / success_criteria / guardrails / 来源 run_id
  2. 群任务完成时**一键「另存为 Playbook」**（从 run_steps 提炼，可编辑后保存）
  3. 建群/派活时可选 Playbook → 注入 system prompt + 任务卡；`Past runs` 标签展示历史用法
- **验收**：跑通一次任务 → 存成 Playbook → 新群引用后行为一致；发送前可 inline 编辑。
- **落点**：`group/playbook_repo.rs`（新）、`commands/playbook.rs`（新）、`GroupDispatch.tsx`（选 Playbook）。

### Phase C · 前端体验纵深（可并行三条线）

**IX-12 DAG 只读拓扑视图**（工作量小、信息增益大）
- 现状：`depends_on` 复选框录入，>4 个任务看不出拓扑。
- 做法：GroupDispatch/Tasks 面板加只读 DAG 渲染（节点按状态着色：等待/进行中/完成/失败），复用 `--status-*` 令牌。
- 落点：`GroupDispatch.tsx` / `TasksPanel` 新组件 + 轻量 SVG。

**IX-8 信息密度滑杆**
- 现状：ProcessPanel 有折叠手风琴 + 自评三态，无密度档位。
- 做法：群聊/运行视图顶部三档切换：只看结论 / 看步骤（含工具摘要）/ 看全部（含参数与原始输出）。
- 落点：`ProcessPanel.tsx`、`GroupRoundtable.tsx`（消息密度）。

**IX-13 启动阶段可见化**
- 现状：建群/冷启动是「加载中」无信息量。
- 做法：把加载替换成阶段化进度（正在装配席位 → 注入能力 → 建立会话 → 就绪），感知性能提升。
- 落点：`GroupsPage.tsx` 建群流程、App 冷启动 splash。

**IX-14 运行回放与分享**
- 做法：基于 runs/run_steps 导出**自包含 HTML 回放**（群协作全过程，可分享），复用 docs/ 下现有 mockup HTML 的渲染风格。
- 落点：新命令 `export_run_replay` + 前端入口（RunInsights / 群详情）。

**IX-10 产出物 diff 与变更集审阅**（依赖 F10）
- 做法：群任务结束给「本次变更集」汇总——改了哪些文件、每个文件谁改的、可一键回滚（消费 F10 changeset 表）。
- 落点：`RunInsights` / `GroupDetail` 变更集面板 + 回滚命令。

## 2. 明确不做（沿用 NG-S1/S2/S3 + §9 反面教训）

- 不做 RBAC / 多租户 / L1-L3 权限层级（NG-S1）；不引常驻服务（NG-S2）；不建 TeamAdmin 层（NG-S3）。
- F13 不做 OAuth 委托全链路（单机用主进程代理即可）；F10 不做 git worktree 全量（单机输出范围声明 + changeset 已够）；F14 不做跨设备记忆同步（NG：跨端同步永不）。
- 不做可视化画布编辑器（NG1，IX-12 只读渲染是折中）。

## 5. 成功指标（M4）

- **技术性（本机可测）**：DB dump 无明文凭证；并发写同文件被拦截且可回滚；记忆蒸馏任务可定时产出；Playbook 可存可引用；DAG/密度/阶段/回放/变更集五件前端可见。
- **产品性**：群协作结束的「本次变更集」成为安全感来源（用户主动使用）；Playbook 复用率 > 0。
- **护栏**：凭证泄露路径 = 0（F13）；并行写损坏 = 0（F10）。

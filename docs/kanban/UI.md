# OneDesktop 看板（Kanban）UI 交互设计

> 状态：交互稿 v1 ｜ 关联 `docs/kanban/PRD.md`
> 设计令牌来源：`src/App.css` `:root`（语义令牌，禁裸 hex/rgb）

---

## 1. 入口与布局

- **入口**：群视图（`GroupsPage`）顶部工具栏新增「看板」标签按钮（图标：三列柱状 `Kanban`），与「聊天 / 产出物 / 运行 / 黑板 / 派活」并列。`board` 标签更名为「黑板」。
- **画布**：横向五列，列间 16px 间距；列内卡片纵向堆叠，卡片间距 10px。
- **自适应**：
  - 宽屏（≥1100px）：五列并排，列宽均分（min 200px）。
  - 中屏（700–1100px）：列横向滚动（overflow-x auto），保持五列不挤压。
  - 窄屏（<700px）：列纵向堆叠（每列一个 section，可折叠）。
- **顶栏（看板内）**：左=群名 + 任务总数；右=筛选（批次下拉、席位下拉、搜索框）+ 刷新按钮。

## 2. 列（Column）

- **列头**：状态图标 + 中文名 + 计数胶囊（计数用状态色 `--status-*-strong`）。
- **状态色**（按令牌）：
  | 状态 | 令牌 | 列头底色 |
  |---|---|---|
  | Pending | `--status-info` | 左侧 3px 信息色条 |
  | InProgress | `--accent` | 左侧 3px 强调色条 |
  | Completed | `--status-success` | 左侧 3px 成功色条 |
  | Failed | `--status-error` | 左侧 3px 错误色条 |
  | Cancelled | `--text-muted` | 左侧 3px 中性条 |
- **空列**：列内显示浅色占位「— 暂无 —」，不折叠（保留拖拽落点）。
- **拖拽悬停**：目标列高亮（边框 `--accent` + 半透明 `--accent` 底色），非法目标列不响应拖入。

## 3. 卡片（Card）

尺寸：列宽 - 32px，圆角 12px，内边距 12px，`luxury-glass` 质感（半透明 + 1px 边框 + 轻 blur）。

```
┌─────────────────────────────┐
│ 研究竞品定价策略  ⛓2  📎3   │  ← 标题（2 行截断）+ 依赖角标 + 产出物芯片
│ 批次 batch_a1 · 理性分析师   │  ← 批次徽章 + 执行席位名
│ ─────────────────────────── │
│ 🔴 卡死 12m · 重试 #1        │  ← 仅 InProgress 且心跳超时 / Failed 显示
└─────────────────────────────┘
```

- **标题**：`description` 截断 2 行（`-webkit-line-clamp:2`）。
- **元数据行**：批次徽章（`batch_id` 缩短显示）+ 执行席位（`assigned_worker ?? worker_id` 经 `resolveName`）。
- **角标**：`⛓N` 依赖数（悬停 tooltip 列出 `depends_on` id）；`📎N` 产出物数（`outputs.length`）。
- **状态附加**：
  - `InProgress` 且 `last_heartbeat` 超时（> F6 timeout，如 60s）或缺失 → 红点「卡死 Nm」，提示恢复。
  - `Failed` → 显示「重试 #N」。
- **交互**：hover 轻微上浮（`translateY(-2px)` + 阴影），`transition 0.2s cubic-bezier(.16,1,.3,1)`；整卡 `draggable`，点击（非拖拽）打开详情抽屉。

## 4. 拖拽与键盘交互

- **拖放（鼠标）**：`draggable` 卡片 → `dragstart` 设 `dataTransfer` 任务 id → 列 `dragover` 阻止默认并校验 `is_valid_transition`（非法列不亮）→ `drop` 调 `taskSetStatus`。落位后用乐观更新（`batches` 本地改）再 `loadDetail` 校正。
- **键盘**：卡片 `tabindex=0`；`Enter/Space` 打开抽屉；`Shift+→/←` 移动到相邻合法列（循环校验，非法跳过）；`Shift+↑/↓` 在同列内移动顺序（仅视觉，不改序，因顺序由后端定）；移动即提交 `taskSetStatus`。焦点环用 `--accent`。
- **非法移动**：前端阻止 + toast「不能将『已完成』拖到『进行中』」；后端 `invalid_transition` 兜底。
- **动效**：卡片落位 60fps 过渡（`transform`/`opacity`），列计数胶囊数字滚动。

## 5. 详情抽屉（Drawer）

点击卡片右侧滑出（`width 380px`，`luxury-glass` 背景），含：
- 标题 + 状态徽章 + 批次 + 席位 + 能力（`capability`）。
- **描述**（全文）+ **验收标准/拆解依据**（`reasoning`）。
- **依赖链**：`depends_on` 列表，每项显示「id → 描述（若在本群 tasks 中 resolve）」+ 其当前状态点。
- **产出物**：`outputs` 列表，可点（文件路径→打开；或匹配 `Deliverable`→`DeliverableDetailDrawer`）。
- **恢复动作**（FR7，复用现有 handler）：
  - `重试`（→`taskRetry`）、`改派`（→`taskReassign`，复用 `TaskRecoveryPanel` 的席位 `select`）、`跳依赖`（→`taskSkipDependency`）。
  - 若该任务属某 `batch_id` 且未终态：`取消批次`（`groupCancelBatch`）。
- 关闭：遮罩点击 / `Esc` / 关闭按钮。

## 6. 空态 / 加载态

- **无任务**：居中插画（单色 SVG）+「该群还没有任务。去『派活』提交一个 SubTask 批次开始。」+ 跳转按钮。
- **加载**：列骨架屏（shimmer，令牌色），复用已加载 `allTasks` 故一般瞬时。
- **切换群/视图**：进入即 `loadDetail`，显示轻量 spinner。

## 7. 主题与无障碍

- 亮/暗：`[data-theme="dark"]` 仅重写令牌，组件不写死颜色。
- 状态不只靠颜色：`Pending` 用 ℹ、`InProgress` 用 ▶、`Completed` 用 ✓、`Failed` 用 ⚠、`Cancelled` 用 ⊘（图标 + 文字双信号）。
- 对比度满足 WCAG AA（参考既有 `groups.css` 元数据色做法：light 用 `-strong`，dark 回亮色）。
- 列/卡 `role="list"`/`listitem`，`aria-label` 含任务描述与状态；拖拽时 `aria-live` 播报「已移动到 进行中」。

## 8. 微交互清单（premium 触感）

- 列计数胶囊数字变化滚动。
- 卡片 hover 上浮 + 阴影；拖拽时源卡半透明。
- 抽屉滑入 `cubic-bezier(.16,1,.3,1)` 280ms。
- 非法落位 shake 微动 + toast。
- 状态变更后目标列高亮脉冲（1 次）。

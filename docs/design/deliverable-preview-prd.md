# 产出物预览功能 · Feature Spec / PRD

> 文档定位：产品需求规格（产品通出品）
> 发起：2026-08-12｜状态：待评审｜版本：v0.1
> 关联：`agent_trace` 轨迹存储（已上线）· 工作区联动计划（L3 资产层）· `DeliverableDetailDrawer`（现状）
> 范围：**产出物（Deliverable）的站内预览体验升级**，打通"产出 → 查看 → 追溯 → 落盘"闭环

---

## 0. 结论先行（TL;DR）

**做什么**：把现在的 `DeliverableDetailDrawer`（纯文本 + 系统程序打开）升级为**统一产出物预览器**——图片内嵌看大图、HTML 沙箱渲染、CSV 表格化、代码高亮；每个产出物可**下钻查看它的产生轨迹**（复用 `agent_trace`）；可一键**保存到工作区**。

**为什么现在做**：`agent_trace` 刚把"过程"变成一等公民存储，产出物预览却还停在"打开文件"——过程可追溯了，产物却无处安放，闭环断在最后一环。

**不做**：不做编辑、不做浏览器、不做 PDF 渲染、不做跨设备云预览。

## 一、背景与问题（Why）

### 1.1 现状

| 维度 | 现状 | 代码位置 |
|---|---|---|
| 产出物来源 | `group_list_deliverables` 聚合三类：圆桌回复 / 任务产出 / 群摘要 | `commands/group.rs:1044` |
| 列表展示 | 表格：类型、作者、内容预览（截断 140 字）、媒体 chips（最多 3 个） | `GroupDeliverables.tsx` |
| 详情打开 | 右侧抽屉：Markdown 渲染 + 媒体卡片（**点开=系统程序**）+ 复制 | `DeliverableDetailDrawer.tsx` |
| 图片展示 | **不能内嵌**——全站无一处使用 `convertFileSrc`，图片一律走系统程序 | 全前端 |
| 媒体来源 | 后端正则从正文抽路径（`extract_media_from_content`）+ attachments 兜底 | `commands/group.rs:85-210` |
| 过程追溯 | `agent_trace` 已上线（P0–P2 落地），但**产出物视图未接入** | `trace_repo.rs` |

### 1.2 用户痛点（一手观察）

1. **预览能力弱**：AI 产出 HTML 报告 → 点开跳出浏览器；产出截图 → 跳出预览程序；产出 CSV → 跳表格软件。**体验割裂，产出物永远"不属于"这个应用**。
2. **看不到产出过程**：一个任务产出 5 个文件，用户想知道"这是哪个工具步骤写的、中途改过几次"——目前无法回答。`agent_trace` 有数据，但没有入口。
3. **附件链路有洞**：工具写出的文件在落库路径硬编码 `vec![]`，媒体只能靠正则从正文抽，**漏网率高**——很多产出物明明有文件却显示不出。
4. **入口分散**：群产出物、任务窗口、chat 附件各是一套展示逻辑，预览交互不统一。

### 1.3 为什么值得做（数据判断）

- 产出物是**单机 AI Agent 应用的核心价值载体**——用户把任务交给 Agent，要的是一份"拿得走、看得懂"的结果。预览是结果的第一消费场景。
- `agent_trace` 已投入落地，轨迹数据**只差一个视图**就能反哺到产出物；复用成本低，边际收益高。
- 竞品（Claude Artifacts / ChatGPT 沙箱）均已证明"**站内产物渲染**"是 Agent 类产品的基础体验，不是锦上添花。

## 二、目标与非目标（Goals & Non-goals）

### 2.1 目标

- **G1**：≥80% 常见产出物类型（文本/Markdown/图片/HTML/CSV/代码）可在站内直接预览，无需跳系统程序。
- **G2**：每个产出物可一键下钻查看"产生它的 agent_trace 过程"（哪个 Agent、哪几步工具调用）。
- **G3**：产出物可一键"保存到工作区"，落盘到项目目录，与工作区资产层打通。
- **G4**：修复附件链路，工具写出文件 → 产出物媒体**完整可见**（不再依赖正文正则兜底）。

### 2.2 非目标（Non-goals）

- ❌ **不做编辑器**：预览只读，编辑/批注属后续独立功能。
- ❌ **不做 PDF 内嵌渲染**：PDF 保持"系统程序打开"（内嵌需引入重型依赖，单机产品不划算）。
- ❌ **不做浏览器**：HTML 用沙箱 iframe 只读渲染，不提供交互式网页浏览。
- ❌ **不做云预览/跨设备**：单机约束，预览全部本地完成。
- ❌ **不做全 MIME 覆盖**：未知类型一律降级为"文件卡 + 打开"，不阻塞主流程。
- ❌ **不重构既有 messages 渲染**：chat 气泡、群聊切条逻辑不在本次范围。

## 四、需求规格（What）

### 4.1 统一预览容器（P0）— 升级 `DeliverableDetailDrawer`

现有抽屉升级为 `ArtifactPreview` 通用预览容器，承载所有产出物类型。**入口保留现状**（产出物列表行点击、任务窗口、chat 附件处可后续接入）。

布局（左→右 / 上→下）：

```
┌────────────────────────────────────────────────────────┐
│ [类型徽标] 标题                   作者 · 时间    [✕]    │
├────────────────────────────────────────────────────────┤
│ ┌──────────┐  ┌──────────────────────────────────────┐ │
│ │  元信息    │  │                                      │ │
│ │ 类型/大小  │  │        渲染区（按类型分发）            │ │
│ │ 路径/来源  │  │                                      │ │
│ │ 产生 Agent│  │                                      │ │
│ ├──────────┤  ├──────────────────────────────────────┤ │
│ │ 附件列表   │  │   [查看产生轨迹 ▸]  [保存到工作区 ▸]   │ │
│ │ (n)      │  │                                      │ │
│ └──────────┘  └──────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

关键行为：
- **侧栏元信息**：类型、大小（新增字段，见 4.4）、本地路径、产生方、时间。
- **附件列表**：横向缩略图条，点击切换主渲染区；图片显示缩略图，文件显示图标卡。
- **底部操作**：复制内容 / 打开系统程序 / 在文件夹中显示（新）/ 查看轨迹（P1）/ 保存到工作区（P2）。

### 4.2 类型化渲染器（P0）— Renderer Registry

按产出物内容/文件扩展名分发到渲染器，未知类型降级：

| 类型 | 判定 | 渲染方式 | 说明 |
|---|---|---|---|
| `markdown/text` | content 或 `.md/.txt/.log/.json` | 复用 `utils/markdown.tsx`（已有） | 默认渲染器 |
| `code` | `.py/.ts/.rs/.js/.css/.html源码…` | 代码高亮块 | 复用 Markdown 代码块能力 |
| `image` | media `type=image` 或扩展名 | **内嵌大图**（`convertFileSrc` + asset protocol，**全站首次启用**） | 支持缩放/平移（基础版：fit 容器 + 点击放大） |
| `html` | `.html/.htm` | **沙箱 iframe**（复用 `RunChangesetPanel` 的 `<iframe sandbox="" srcDoc>` 模式） | 禁脚本、禁弹窗 |
| `csv/tsv` | `.csv/.tsv` | 表格化渲染（首行表头 + 行数统计） | 数据量阈值保护 |
| `pdf/binary` | 其余 | 文件卡 + "系统程序打开" | 不内嵌，明示降级 |

**渲染器注册表**：`src/components/artifacts/renderers/` 下按类型独立组件 + 一个 `rendererFor(deliverable)` 纯函数分发（与项目"判定逻辑抽纯函数"纪律一致）。

### 4.3 产出轨迹下钻（P1）— 与 `agent_trace` 打通

- 产出物 → 产生它的任务/会话 → 该 run 的 `agent_trace`（`scene=worker`）。
- 预览面板底部"查看产生轨迹 ▸"→ 展开轨迹视图：
  - 按 `seq` 回放 thinking → intent → tool_call → tool_result → observation → answer；
  - **产出文件高亮对应 tool_result**（哪个工具调用写出的文件，在轨迹里反显）；
  - 复用 `ProcessPanel` 的渲染组件（同源 `traceToItems`，**不新写一套**）。
- 数据关联：`Deliverable` 增加 `trace_ref`（可选，产出物所属 run_id / session_id），由 `group_list_deliverables` 填充。

### 4.4 附件链路修复（P2）— 引擎侧捕获工具写出文件

现状漏洞（治标在正则抽取，治本在落库）：
- 落库路径硬编码 `vec![]` → 工具写出的文件不进 attachments；
- 引擎侧捕获工具写出的文件路径 → 写入 run/产出物 attachments → 媒体完整可见。

改动点：
- 引擎工具执行层：识别"写出类"工具结果（文件写入、代码执行落盘、截图保存…），提取产物路径；
- `Deliverable`/`DeliverableMedia` 增加：`size`（字节）、`mime`（判定类型）、`mtime`；
- `group_list_deliverables` 直接读 attachments，正则抽取降级为兜底。

### 4.5 保存到工作区（P2）— 与 workspace 联动

- "保存到工作区 ▸"→ 将产出物内容/媒体落盘到 `{workspace.path}/.one-desktop/artifacts/{日期}/`；
- 落盘后产出物 path 更新为工作区内路径（在预览侧栏可见）；
- 与 `workspace-linkage-plan` L3 资产层衔接：变更集/灵感/产出物按工作区归集。

## 五、交互设计要点

1. **零跳转**：默认全部站内预览；"系统程序打开"降级为显式操作而非默认行为。
2. **渐进展开**：预览默认抽屉宽度 560px；图片/HTML 可"展开全宽"（复用现有 drawer 展开模式）。
3. **键盘可达**：Esc 关闭、方向键切换附件（复用 `useDialogA11y`）。
4. **加载态**：图片懒加载 + 骨架屏；大文件（>5MB）内嵌前提示"文件较大，建议系统程序打开"。
5. **空态/失败态**：文件不存在 → 明示"文件已移动或删除"并禁用内嵌；渲染失败 → 降级为文本预览 + 打开按钮。
6. **安全性**：HTML 一律 `sandbox=""`（无 allow-scripts）；asset protocol 路径经 scope 校验，杜绝任意文件读取。

## 六、技术方案要点（对齐既有纪律）

| 纪律 | 本方案落点 |
|---|---|
| 内核纯净度（kernel 禁 `use tauri::`） | 预览全在前端；后端仅补 `size/mime` 字段与附件落库，无新增 Tauri 依赖 |
| ADDITIVE 迁移（ADR-006） | 产出物表/媒体表仅加列，不动既有数据 |
| 判定逻辑抽纯函数 | `rendererFor()`、`detectMime()`、`formatBytes()` 均纯函数 |
| 复用而非重写 | 轨迹视图复用 `ProcessPanel`/`traceToItems`；HTML 复用 `RunChangesetPanel` 沙箱模式；Markdown 复用 `utils/markdown.tsx` |
| 测试基线 | 新增 `rendererFor`/`detectMime` 单测；E2E 补"图片内嵌预览 + HTML 沙箱 + 轨迹下钻"用例；`tauriMock.ts` 补新命令 mock |
| UI 令牌 | 全部走 `App.css :root` 令牌，禁裸 hex |

## 七、竞品参照（客观对比）

| 竞品 | 产出物预览做法 | 可借鉴 | 我们不必跟 |
|---|---|---|---|
| **Claude Artifacts** | 对话内嵌代码/网页/文档渲染，可展开全屏 | "产出物即一等视图"，预览可展开 | 全屏画布复杂度（单机场景过重） |
| **ChatGPT 数据沙箱** | 产出 CSV/PNG/代码文件，点击查看/下载 | 文件级元信息（类型/大小）展示 | 云端沙箱执行（单机不做） |
| **Cursor / IDE 内建预览** | Markdown/图片/HTML 就地预览，不跳外部程序 | "就地预览优于跳系统程序"正是我们的目标态 | IDE 的编辑器能力（Non-goal） |
| **飞书/腾讯文档预览** | 列表点击 → 侧栏预览 | 列表 + 预览侧栏的轻交互 | 在线协同/权限体系 |

> 结论：我们不追任何竞品的平台级能力，只做"单机场景下产出物的第一消费体验"——站内看、能追溯、可带走。

## 九、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| HTML 预览安全（恶意脚本/本地文件读取） | 高 | 一律 `sandbox=""` 无脚本；asset protocol scope 白名单校验路径；不接受用户文件进 iframe 的任意 URL |
| 图片内嵌性能（超大图/大量图） | 中 | 懒加载 + 压缩阈值（>5MB 提示降级）；列表缩略图只取前 3 |
| 附件链路修复牵动引擎（回归风险） | 中 | 落库加列 additive；引擎捕获先做"写出类工具"白名单，灰度观察 |
| 轨迹下钻复用 `ProcessPanel` 耦合加深 | 中 | 抽出共享轨迹视图组件，`ProcessPanel` 与预览面板共同引用，不各写一套 |
| 工作区路径变更导致预览失效 | 低 | path 不可达时明示降级（见交互 5），不自动修复 |

## 十、分期实施（Roadmap）

| 阶段 | 范围 | 依赖 | 验收 |
|---|---|---|---|
| **P0 · 预览器骨架** | 统一容器 + Markdown/Code/Image/HTML/CSV 渲染器 + 元信息侧栏 + 附件缩略图条 | 无（纯前端 + 现有数据） | 图片内嵌可见、HTML 沙箱渲染、未知类型降级打开 |
| **P1 · 轨迹下钻** | `Deliverable.trace_ref` + 预览面板"查看轨迹" + 产出文件反显 tool_result | P0 | 从产出物可下钻看到完整过程链 |
| **P2 · 附件链路 + 工作区** | 引擎捕获写出文件落库 + `size/mime/mtime` + 保存到工作区 | P1 | 工具产出文件在预览中完整可见；一键落盘工作区 |

**建议落地顺序**：P0（体验立竿见影，纯前端无回归）→ P2 附件链路（数据完整是预览的地基，可提前与 P0 并行）→ P1 轨迹下钻（体验增量）。

## 十一、验收标准（Acceptance Criteria）

- [ ] 产出物列表点击图片类型产出物 → 站内显示大图，无系统程序跳出
- [ ] HTML 产出物 → 沙箱 iframe 渲染，右键/脚本全部禁用
- [ ] CSV 产出物 → 表格化渲染，行数正确
- [ ] 每个产出物预览可见：类型/大小/路径/产生方/时间
- [ ] 带 `trace_ref` 的产出物可展开产生轨迹，轨迹中产出文件所在 tool_result 高亮
- [ ] 工具写出的文件出现在产出物媒体列表（不再依赖正文正则）
- [ ] "保存到工作区" → 文件落盘 `{ws}/.one-desktop/artifacts/{date}/`，侧栏路径更新
- [ ] 文件被删除 → 明示降级，不崩溃、不白屏
- [ ] `npm run check:ts` / `check:rust` / `check:kernel` 通过；E2E 新用例全绿

# 圆桌（群协作）UI 交互重设计 v2

> 设计定位：**Agent 交互 UI 设计专家视角下的重设计**。聚焦核心闭环，彻底贴合 Apple HIG，并 100% 复用项目既有设计系统（`App.css` 令牌 + `Icons.tsx` 单色 SVG）。相对 v1 的改动不是"加功能"，而是"把圆桌这件事讲清楚"。
>
> 配套交付：`docs/ui-mockup-roundtable-v2.html`（可交互演示，含深色模式 / 席位聚焦 / 卡片展开 / 任务看板 / 建群弹窗）。

---

## 1. 先说问题：v1 为什么不够好

v1（`ui-design-roundtable.md` + `ui-mockup-roundtable.html`）能跑通，但有三处硬伤，恰好都违背项目设计铁律：

| 问题 | 表现 | 违背了什么 |
|------|------|-----------|
| **满屏 emoji** | 导航💬📋🧩、成员🧠💬、步骤⚡👁🔐 | `Icons.tsx` 单色 SVG 是唯一图标来源，禁止彩色 emoji |
| **"圆桌"没有视觉表达** | 只是「左成员栏 + 中聊天 + 右文件树」三栏，和任意群聊无差异 | 需求原意是"多方围坐一张桌子"的协作隐喻没落地 |
| **焦点发散** | 右侧常驻文件树占用 240px，弱化核心闭环 | 用户要求"聚焦核心功能"，非核心的 workspace 树应后置 |

结论：**把"圆桌"做成了一个普通聊天室**。

---

## 2. 重设计的核心思路

### 2.1 锚定核心闭环（只服务这条线）
```
人类发需求  →  群主拆解并派活  →  多 Worker 并行执行（卡片）  →  实时状态可见  →  群主验收 / 人类采纳
```
界面上的一切元素，都在让这条线**更短、更直、更可见**。任何偏离这条线的东西（文件树、设置）默认收起或后置。

### 2.2 把"圆桌"变成签名视觉元素
新增 **「席位条（Seats Strip）」** 作为圆桌的视觉锚点：
- 所有参与者（群主 + Workers）以**头像座位**一字排开，背后是一道极淡的圆形渐变，**隐喻"围坐圆桌"**。
- 群主居首、带 crown 徽标与 accent 环，明确"主持者"身份。
- 每个座位用 **状态环（ring）** 表达 Idle / Busy（旋转）/ Offline（暗）/ Error，**一眼扫完全局状态**——这正是 US3（实时掌握全局）的解法。
- 点击任一座位 → 聚焦该 Worker（其它执行卡片淡出），实现"按成员看进展"。

这是 v1 缺失的、也是"圆桌"二字最该有的样子。

### 2.3 执行卡片即进度，不再割裂
保留"讨论气泡 + 内嵌执行卡片"混合模型（PRD 已定，NG4 不做独立任务页），但把卡片**重做成自带进度条的工作单元**：header 直接显示 `进度条 + 子任务计数 + 状态`，默认展开当前活跃者、折叠完成/等待者，降低噪音。

### 2.4 任务看板作为"可关闭的全局视图"
把"实时看每个 Worker 进度"抽成**可折叠右栏"任务看板"**（聚合所有子任务 + 进度条），而非常驻文件树。默认展开、可一键收起——核心功能常驻，但给内容区让出空间。

## 3. 信息架构（v2）

```
Sidebar（248px，复用现有）
├── 导航：对话 / 任务 / 扩展（SVG 图标）
└── 圆桌（新增分区）
    ├── ● 市场调研群（Active）
    ├── ◐ 官网重构群（Paused）
    ├── ○ 竞品分析（Archived，只读）
    └── ＋ 创建圆桌

Main（点击圆桌 → 圆桌视图）
├── TopBar：返回 ｜ 圆桌名 ｜ 状态胶囊(运行中●) ｜ [任务看板][深色][⋯生命周期]
├── Seats Strip ★签名：群主 + Workers 头像座位 + 状态环 + 加座（动态席位）
├── Stage（flex:1）
│   ├── 聊天流：人类气泡 / 群主拆解气泡(@提及高亮) / 内嵌执行卡片(进度条+可折叠) / 系统消息(采纳产物)
│   └── Composer：发需求 / @成员 / 附件 / 发送
└── 任务看板（右栏，可折叠）：子任务聚合 + 进度条 + 状态
```

差异点：v1 的三栏（成员 + 聊天 + 文件树）→ v2 的 **席位条（顶部）+ 聊天流（主）+ 看板（可折叠右栏）**。文件树从 v1 常驻降级为"在 Finder 打开"按钮（保留能力，不占主界面）。

## 4. 关键界面与交互

### 4.1 席位条（Seats Strip）—— 签名元素
- **布局**：横向滚动的一排"座位"，背后淡圆渐变作圆桌隐喻；群主带 crown + accent 环。
- **状态环（ring）**：Idle=`border-heavy` 灰环 / Busy=`accent` 环 + 旋转 / Offline=暗 40% / Error=`status-error` 红环。
- **交互**：hover 上浮 2px；点击聚焦该 Worker（其余执行卡片 `.dim`）；群主座位取消聚焦（恢复全显）。
- **加座**：虚线圆按钮，触发动态席位加入（对应 P1 动态席位）。

### 4.2 执行卡片（workflow-group 复用，重做 header）
- header：`头像 + 名称 + 进度条(含%) + 子任务计数 + 状态 + 展开箭头`。
- 进度条 fill 用 `--accent`，完成态转 `--status-success`。
- body：复用 `.react-step` / `.tool-call-card` / `.thinking-block` 风格；**HITL 内联**在卡片内（批准/拒绝），`session_id` 随事件带。
- 默认：活跃者展开、等待/完成者折叠，点击 header 切换。

### 4.3 系统消息 + 验收闭环
- "子任务全部完成，请群主验收"——居中胶囊（`--accent-soft` 底 + `--status-info-strong` 文字，遵守状态文字强色令牌）。
- 内嵌 **「采纳产物」** 按钮 → 卡片标 done、artifacts 落盘、圆桌闭环（toast 反馈）。这是核心闭环的收口。

### 4.4 Composer（主操作区）
- Apple 风格圆形输入框：聚焦时 `border-focus` + `accent-soft` 光环。
- 工具：附件、@成员（accent 高亮）；发送为 accent 实心圆按钮，`⌘/Ctrl+Enter` 发送。
- 空输入时发送禁用（降噪、防误触）。

### 4.5 任务看板（可折叠右栏）
- 聚合所有子任务：`头像 + 名称 + 状态徽标(已完成/执行中/排队中) + 描述 + 进度条`。
- 状态徽标用中性底 + 强色文字（项目 a11y 规范，禁止 tint 底）。
- 顶部栏一键收起（`boardToggle`），收起后内容区占满。

### 4.6 创建圆桌弹窗（重做）
- 复用 `.modal-overlay` / `.modal-content`（radius-xl、shadow-lg）。
- 字段：名称 / 目标 / 群主(select) / **席位配置（三段式 SegmentedControl：静态名单 / 动态加人 / 能力匹配）** / 初始成员（复选）。
- 段控切换"静态名单"才显示成员多选——按需展开，减少默认认知负荷。

### 4.7 空态（圆桌无人发言时）
- 中央一圈虚线"圆桌" + 几个空座位图标，文案"发起第一条需求，群主会帮你拆解并派活" + 主操作按钮。
- 把"圆桌"隐喻在空态也讲清楚，而非复用通用空态。

## 5. 相对 v1 的 6 处关键重构（清单）

1. **emoji → 单色 SVG**：全部图标改为 `Icons.tsx` 风格的 `stroke="currentColor"` 内联 SVG，零彩色 emoji。导航/成员/步骤/工具/状态全部合规。
2. **新增席位条（圆桌隐喻 + 全局状态）**：用头像座位 + 状态环替代"左侧成员小点列表"，既表达圆桌、又一眼看全局。
3. **三栏 → 席位条 + 主聊天 + 可折叠看板**：释放被文件树占用的 240px；workspace 降级为"在 Finder 打开"按钮。
4. **执行卡片自带进度条**：header 直接显示进度与子任务计数，无需点开即知进展。
5. **验收闭环显式化**：系统消息内嵌「采纳产物」按钮 + toast 反馈，核心闭环有收口。
6. **深色模式 + 令牌严格化**：全程只用 `App.css` 语义令牌（含 `--status-*-strong` 状态文字强色），`[data-theme="dark"]` 仅重写令牌、组件零改动；mockup 可一键切换验证。

## 6. 组件 → 真实令牌 / 图标映射（落地不漂移）

| 元素 | 令牌 / 类 | 说明 |
|------|-----------|------|
| 席位头像 | `--bg-tertiary` 底 + `--text-secondary` 字 + 状态 `ring` | ring 用 `--accent`/`--border-heavy`/`--status-error` |
| 状态胶囊 | `--accent-soft` 底 + `--status-info-strong` 字 | 运行中带 pulse 点 |
| 执行卡片 | `--bg-elevated` + `border-light` + `shadow-sm` + `radius-lg` | 复用 workflow-group 语义 |
| 进度条 | fill `--accent`（完成 `--status-success`） | 轨道 `--bg-tertiary` |
| HITL 条 | `--accent-soft` 底 + `color-mix(accent 24%)` 边 | 批准=`--accent-strong` 白字 |
| 主按钮 | `--accent-strong` 底 + `--text-inverse` 字 | 白字对比度 ≥4.5:1（解耦链接色） |
| 图标 | 全部内联 SVG `stroke="currentColor"`，尺寸 18/22/15 | 遵循 `Icons.tsx` 风格，禁 emoji |
| 圆角 / 间距 / 字号 | `--radius-*` / `--space-*` / `--text-*` | 禁止裸值 |
| 深色 | `[data-theme="dark"]` 仅重写令牌 | 组件零改动 |

## 7. 状态、异常、可访问性

- **成员状态环**：Idle / Busy(旋转) / Offline(暗) / Error(红)，与令牌一一对应。
- **执行卡片状态**：执行中(accent 脉冲) / 完成(success) / 错误(error)。
- **空态**：虚线圆桌 + 空座位（见 4.7）。
- **错误态**：调度失败用 banner；worker 结构性失败 → 系统消息 `@人类` 请求决策。
- **a11y**：状态一律用"强色文字 + 中性底"（不用浅 tint 底，满足 WCAG AA 4.5:1）；图标 `currentColor` 随主题；焦点环 `--accent-soft`；席位按钮可聚焦。

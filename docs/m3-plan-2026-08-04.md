## 一、M3 要解决什么

M2 解决了「能用、敢用、会用」——Agent 有工具、过程看得见、Worker 能审批、单聊可升级。
M3 解决的是**「从用户逐个派活，走向 Agent 之间自组织」**，同时把 OneDesktop 的**桌面端独占优势**做实。

### 竞品坐标（2026-08-04）

| 维度 | M2 后的 OneDesktop | 阿里 AgentTeams | 港大 AgentSpace | Claude Code Teams |
|------|-------------------|-----------------|-----------------|-------------------|
| Agent 定义可移植 | ❌ 库内 CRUD | ✅ TeamSpec 模板 | ✅ 签名 persona-card 导出 | ✅ `.claude/agents/*.md` |
| Worker 间通信 | ❌ 星形拓扑 | ✅ peerMentions 策略 | ✅ 频道准入 | ✅ Mailbox 点对点 |
| 通信拓扑策略 | ❌ 全员扇出 | ✅ CRD 字段 | ✅ 频道隐私 | ✅ Lead 中枢 |
| 任务防死锁 | ❌ 无心跳超时 | ✅ 容器重启 | ✅ daemon 监控 | ⚠️ 已知限制 |
| CLI 诊断 | ❌ 只能跑 | ✅ Matrix 解耦 | ✅ 8 种 harness 诊断 | — |
| Skill 分级加载 | ❌ 全量注入 | ✅ ReMe 三层 | ✅ 知识库 | ✅ L1/L2/L3 三级预算 |
| 结构化黑板 | ❌ 自由文本 | ✅ MinIO 共享 | ✅ 知识库 | ✅ 共享任务列表 |
| 零基础设施 | ✅ **独占** | ❌ Docker+Matrix | ❌ PG+Google | ✅ |

**结论**：M2 补齐了运行期可见性，但**协作深度和可移植性**仍是短板。M3 的核心目标是：

1. **让 Agent 定义能进出**——从 `.claude/agents` 一键导入，这是桌面端结构性优势
2. **让 Worker 能自组织**——先有拓扑策略，再放开互相通信
3. **让协作不卡死**——任务心跳、依赖链超时、CLI 诊断
4. **让上下文更省钱**——Skill 三级预算 + 结构化黑板

## 三、实施顺序与依赖

```

    ├─ Agent Manifest 规范（AgentProfile 扩展字段）
    ├─ .claude/agents ↔ Manifest 双向适配器
    ├─ 内置席位模板库（研究员/评审员/执行者/汇总者）
    └─ IX-16 能力体检面板（建群时跑一次 preflight）
        ↑ 数据源来自 F11 的 preflight()，所以 F11-① 要先做

  F12 通信拓扑策略 —— 必须先于 F5
    ├─ 群配置加 peer_mentions + visible_to
    ├─ post()/broadcast() 按策略过滤

         ↓
  F5 Worker 间直接通信 —— 依赖 F12 的拓扑约束
    ├─ send_to_worker 内置工具（附带上下文范围选项）
    ├─ Worker 空闲/失败自动通知群主
    └─ broadcast 二次确认（成本随规模倍增）

Phase 3 · 可靠性与省钱（可并行）
  线 a：F6 任务心跳与防死锁
    ├─ 任务加 heartbeat_at + deadline
    ├─ 调度器 tick 检测超时 → 标 Failed + 通知群主
    └─ 「重试 / 改派 / 跳过依赖」三个动作

  线 b：F8 Skill 三级预算
    ├─ capabilities_block() 只注 L1 元数据（~100 token）
    ├─ 命中后才读 L2 正文（<5k token）
    ├─ L3 捆绑文件按需读取（未访问 = 0 token）
    └─ 接通 scheduler 的 skill action

  线 c：F7 结构化共享黑板
    ├─ 群级 shared_state（建群时声明 key + 类型 + 默认值）

    ├─ 条件派活可写表达式

  F11 CLI 执行器可诊断

    ├─ session_fallback() —— 会话 ID 丢失时降级为一次性调用

Phase 5 · 体验面（可并行三条线）
  IX-3 Work Log 折叠手风琴
    ├─ ProcessPanel 从平铺改为折叠手风琴
    ├─ 每步状态点（成功/有警告/失败）+ 耗时
    └─ 自评等级由引擎按 stop_reason + isError 自动生成

  IX-6 全局待办收件箱
    ├─ 侧边栏加「待办」入口 + 未读角标
    ├─ 聚合三类：待审批 / 失败任务 / Worker 提问
    ├─ 点击跳转到对应群 + 定位消息
    └─ 系统通知 + Dock 角标
```

## 四、各需求详述

### F4 · Agent 定义可移植（P1-α，桌面端独占优势）

**对标**：Claude Code `.claude/agents/*.md`（事实标准，字段同构）· AgentSpace 签名 persona-card 导出

**为什么第一个做**：
- 桌面端独占红利——云端/服务端产品做不到「读本机 `.claude/agents/` 目录」
- AgentTeams 和 AgentSpace 已走到「签名导出 + 模板化」，OneDesktop 连导入都没有
- 与 M2 已有的 `SKILL.md` frontmatter 解析能力同源，可复用

**做法**：
1. 扩展 `AgentProfile`：加 `disallowed_tools` / `permission_mode` / `max_turns` / `isolation` 字段
2. 写 `.claude/agents/*.md` ↔ Agent Manifest 双向适配器（frontmatter 解析复用 skill 模块）
3. 扩展页加「导入本地 Agent」入口——扫描 `~/.claude/agents/` 和 workspace 内 `.claude/agents/`
4. 内置 4 个席位模板：研究员 / 评审员 / 执行者 / 汇总者
5. 导出能力：AgentProfile → `.claude/agents/*.md` 文件（敏感字段默认脱敏）

**验收**：
- [ ] 从 `.claude/agents/` 导入一个 Agent，字段完整映射到 AgentProfile
- [ ] 导出的 `.md` 文件可被 Claude Code 直接使用
- [ ] 建群时可选内置模板，一键填充席位配置

**落点**：`group/agent_profile.rs` · `skill/manager.rs`（复用 frontmatter 解析）· `extensibility/ExtensibilityPage.tsx`

---

### F12 · 通信拓扑策略（P1-β，F5 的前置）

**对标**：AgentTeams `peerMentions` / `channelPolicy` · AgentSpace 频道准入

**为什么在 F5 之前**：没有拓扑策略就放开互相 @，会立刻退化成消息风暴 + 成本失控

**做法**：
1. 群配置加 `peer_mentions: bool`（默认 false）+ 席位级 `visible_to: Vec<SeatId>`（默认全体）
2. `post()` 按策略过滤投递目标——非 @ 的 Worker 不收到消息，上下文更干净
3. `broadcast()` 按 `visible_to` 收窄范围——省 token
4. UI 建群弹窗加「协作拓扑」三选一预设：
   - **星形**（默认，群主中枢，peer_mentions=false）
   - **全连通**（peer_mentions=true，所有人可互 @）
   - **自定义**（逐席位配 visible_to）

**验收**：
- [ ] 星形拓扑下，Worker 之间互 @ 不投递
- [ ] 全连通拓扑下，Worker 互 @ 正常扇出
- [ ] broadcast 只投递给 visible_to 内的席位

**落点**：`group/group.rs` · `group/roundtable.rs`（post/broadcast 过滤）· `CreateGroupModal.tsx`

---

### F5 · Worker 间直接通信（P1-γ，依赖 F12）

**对标**：Claude Code Mailbox（SendMessage 点对点 + broadcast）· Lindy Agent Message Received 触发器

**做法**：
1. 新增 `send_to_worker` 内置工具：目标从群成员名册选，附带上下文范围选项（降 token）
2. Worker 空闲/失败时自动通知群主（对标 Claude Code TeammateIdle）
3. broadcast 做显式二次确认 + 成本提示（「预计 N 次调用 / 约 ¥Y」）
4. 被拒操作不能转交其他 Worker 绕过（Claude Code 的安全纪律）

**验收**：
- [ ] Worker A 通过 `send_to_worker` 向 Worker B 发消息，B 收到并回复
- [ ] Worker 空闲时群主收到通知
- [ ] broadcast 有二次确认 + 成本预估

**落点**：`agent/tools/` 新增工具 · `group/roundtable.rs`（复用 RoundtableBus）

---

### F6 · 任务心跳与依赖链防死锁（P1-δ）

**对标**：n8n `Limit Wait Time` · Claude Code 已知限制（官方承认状态滞后导致依赖卡死）

**做法**：
1. 任务加 `heartbeat_at` + `deadline` 字段
2. 调度器 tick 检测超时任务 → 标 Failed + 通知群主
3. 提供三个动作：「重试 / 改派他人 / 跳过依赖」
4. `TeammateIdle` 式空闲检测归入此处

**验收**：
- [ ] Worker 卡死后，deadline 到期自动标 Failed 并通知群主
- [ ] 依赖链上的后继任务在前行 Failed 后可选择「跳过依赖」

**落点**：`group/scheduler.rs` · `group/task_board.rs` · `scheduler/engine.rs`（复用 1s ticker）

---

### F8 · Skill 三级预算加载（P1-ε）

**对标**：Claude Code L1 元数据 ~100 token / L2 正文 <5k / L3 捆绑文件按需（未读 = 0 token）

**为什么值得**：多 Worker 场景下每个席位有独立上下文，省的 token 是**乘法关系**——5 个 Worker × 每席位省 3k token = 单轮省 15k

**做法**：
1. `capabilities_block()` 的 skill 注入改为只注 L1 元数据（name + description + when）
2. Agent 命中 skill 后才读 L2 正文（<5k token）
3. L3 捆绑脚本/文件按需读取，未访问 = 0 token；脚本只回收输出不进上下文
4. 接通 scheduler 的 skill action（当前明确记录「未接通」）
5. 约束：description 必须同时写清 what + when

**验收**：
- [ ] 5 个 skill 只命中 1 个时，上下文只含 L1 × 5 + L2 × 1
- [ ] 定时任务的 skill action 正常执行

**落点**：`skill/manager.rs` · `group/agent_profile.rs`（capabilities_block）· `scheduler/engine.rs`

---

### F7 · 结构化共享黑板（P1-ζ）

**对标**：Flowise Flow State（预声明 key + 默认值，不能新建 key）· AG2 ContextVariables（表达式条件）

**做法**：
1. 群级 `shared_state`：建群时声明 key + 类型 + 默认值
2. Worker 通过 `read_state` / `update_state` 内置工具读写，**不能新建 key**
3. 条件派活可写表达式（如 `${research_done} == true`）
4. 前端把黑板渲染成表格实时展示

**验收**：
- [ ] Worker A 写入 `shared_state.research_result`，Worker B 能读到
- [ ] Worker 不能新建未声明的 key
- [ ] 前端群详情显示黑板表格

**落点**：`group/group.rs` · `group/roundtable.rs`（build_worker_seed 注入黑板）· 新增内置工具 · `GroupsPage.tsx`

---

### F11 · CLI 执行器可诊断（P1-η）

**对标**：AgentSpace AgentRouter——8 种 harness，每种有独立诊断策略（per-provider preflight + classify_failure + session_fallback + tool approval bridge）

**做法**（三个方法 + 一个 bridge）：
1. `preflight()` —— 启动前检查：可执行文件存在性、版本兼容、认证状态、模型可用性
   - 把失败前置到席位配置时，而不是任务执行到一半
   - **F4 的 IX-16 能力体检面板直接消费这个数据**
2. `classify_failure()` —— 退出码 / 空输出 / 超时 → 可枚举原因（timeout / nonzero_exit / empty_response / auth_failure / model_unavailable）
3. `session_fallback()` —— 会话 ID 丢失时降级为一次性调用
4. **tool approval bridge** —— 外部 CLI 的权限请求走 M2 已落地的 ApprovalBroker 冒泡审批
   - 不让外部席位成为权限黑洞

**验收**：
- [ ] Claude Code CLI 不可执行时，preflight 报错并提示修复方式
- [ ] 外部 CLI 请求执行危险操作时，审批卡片弹出（走 ApprovalBroker）
- [ ] 会话 ID 丢失时自动降级为一次性调用，不整轮失败

**落点**：`agent/executor/cli.rs` · `agent/permission.rs` · `agent/approval.rs`

### IX-3 · Work Log 折叠手风琴

**对标**：Devin Work Log——每步带状态点 + 时间戳 + 耗时，可跳到出问题的那一步

**做法**：
1. `ProcessPanel.tsx` 从平铺列表改为折叠手风琴
2. 每步左侧状态点（成功/有警告/失败），右侧耗时
3. 自评等级由引擎按 `stop_reason` + `isError` 自动生成，不需要额外 LLM 调用
4. 配色用项目令牌 `--status-*-strong`，不用 emoji

**落点**：`ProcessPanel.tsx`

### IX-6 · 全局待办收件箱

**对标**：LangGraph Agent Inbox——Gmail 式收件箱收敛所有中断，支持「Open in Studio」跳回现场

**做法**：
1. 侧边栏加「待办」入口 + 未读角标
2. 聚合三类：待审批工具调用 / 失败需决策的任务 / Worker 主动提问
3. 点击跳转到对应群 + 定位到那条消息
4. **桌面端独有**：系统通知 + Dock 角标——Agent 后台跑长任务时关键体验差异

**落点**：`Sidebar.tsx` · 新增 `features/inbox/` · Tauri 系统通知 API

---

### IX-7 · 从任意消息分叉重跑

**对标**：LangGraph Studio `Edit state → Fork` + `Re-run from here`

**做法**：
1. 圆桌消息 hover 出两个动作
2. **Fork** = 改状态后分叉重跑（build_worker_seed 按 `seq < broadcast_seq` 截历史，数据基础已存在）
3. **Re-run** = 不改状态、换模型/配置重跑

**落点**：`GroupsPage.tsx`（圆桌消息气泡）· `group/roundtable.rs`

---

### IX-16 · 能力体检面板

**对标**：AgentSpace Diagnostics——把「为什么这个 Agent 干不了活」变成可枚举清单

**做法**：
1. 扩展页新增「能力体检」
2. 对每个席位输出一行结论：
   - 模型可达性（Provider Key 是否有效）
   - MCP Server 连通性与工具数
   - 外部 CLI 可执行性与版本（消费 F11 的 `preflight()`）
   - 引用的 Skill 是否存在
   - workspace 路径是否可写
3. 每条给出「去修复」跳转
4. **建群时也跑一次**，把「席位不可用」前置到配置期

**落点**：`extensibility/ExtensibilityPage.tsx` · `agent/executor/cli.rs`（preflight 数据源）

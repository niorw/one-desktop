DOC设计意图

1核心设计目标

  • 从"群信息板"变为"群管理控制台"——视觉重量从展示转向行动
  • 信息架构三层：概览（一眼看完）→ 成员（核心运营对象）→ 设置 / 操作（可折叠）
  • 所有现有功能零损失：4 个统计、3 类席位、tag 体系、群主标记、进度环、状态点、tokens / 耗时、工作空间路径、主操作（添加 / 派发 / 回退）

2主要改动

V4 当前痛点
头部 2×2 占 50% 高度但不传递"该做什么"
每个成员都挂全套 tag + 度量，扫读速度慢
工作空间长路径破碎 + 无操作
底部 3 个圆按钮孤立，主操作不突出
V5 解法
4 卡压成一行概览条（省 60% 高度）
第二行任务驱动（当前工具 + 状态）— 扫读 1 秒
路径显示目录名 + Finder/复制操作
主操作"派发任务"实色突出，次操作并排

3关键交互

  • 成员行 hover：右上角浮出"重跑 / 编辑 / 移除"操作（icon-only，默认隐藏，符合"工程师工具感"）
  • 状态 badge：icon + 颜色 + 文字三通道，对色盲友好；运行中带呼吸 pulse 动画
  • 任务状态从抽象的"空闲"改为具体的"运行中 + 当前工具"——一眼知道 worker 在做什么
  • 添加席位 → 虚线占位区（dashboard 卡片文化的常见做法），点击直接打开 preset 选择器
  • Section 可折叠：群设置默认折叠（不常用），工作空间和成员默认展开
  • 键盘：⌘+↵ 派发任务 / ⌘++ 添加席位

4视觉决策

对比策略：未引入新色——token 全部沿用现有 --accent / --status-warning / --bg-soft。 视觉变化来自信息密度、留白节奏、卡片层级。 群主识别从纯 tag 升级为2px 左边框 + tag——一眼能数出"群里谁是主"。

5落地清单

  • tsx：1 文件改写（保持 props 不变；新增 wsRow hover affordance + 概览条）
  • css：~80 行（新增 .v5-*，旧 .v4-* 待 v5 收敛后删除）
  • i18n：新增 groups.action.dispatch 等 3 key
  • dark theme：一次性同步（CSS 变量驱动，全白名单方案）
设计意图 可落地 WCAG AA 保留全部现有元素

i设计哲学

当前面板体现了一个典型的"功能堆叠"问题：每个元素都有合理性，但组合起来读不出意图。 V5 重塑的底层命题——设计师的工作不是堆功能，是排意图。 "群主 panel" 的用户意图只有 4 件：① 群健康吗 ② 谁在干嘛 ③ 工作空间在哪 ④ 下一步做什么。 V5 把这 4 件事放在面板从顶到底的视觉层次里。

ii取舍明细

  • 保留：4 个统计指标的所有语义（席位/执行/任务/验收），只是视觉密度变了
  • 保留：群主 tag、席位类型 tag、状态点、tokens/耗时、进度环、工作空间显示
  • 保留：3 个底部操作（添加/派发/回退），但重新分层（主+次）
  • 新增：成员 hover 操作（重跑/编辑/移除）、工作空间操作（Finder/复制）、可折叠 section、添加席位虚线占位
  • 删减：无。所有 V4 元素都在 V5 找到位置

iii实现成本

ttsx 1 文件改写（props 不变），css +80 行（新增 v5-*，旧 v4-* 等 V5 收敛后再删）， i18n 3 个新 key，dark 主题自动同步（CSS 变量驱动）。 预计开工 + 评审 + E2E 基线更新 = 半天工作量。

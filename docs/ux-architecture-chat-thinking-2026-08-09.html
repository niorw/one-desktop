Chat 模式「模型思考」交互架构重设计

把当前散落在 3 处的「思考」实现统一为永远在场的 ThinkingLayer + 单一 Turn 状态机，让思考可见、可控、跨模式一致,消除长任务期间的"静默空白"断点。

文档日期 2026-08-09 状态:设计草案 v1 范围:chat(session) 优先,架构上统一 group 角色:用户体验架构师 / ArchitectUX

结论先行

当前 chat 的思考交互有 3 套互相独立的实现、且只在 reasoner 模型下才出现。默认模型 deepseek-v4-flash 不吐 reasoning,导致用户在长任务"思考中"阶段只看到三个点的 spinner,既不知道在想什么、也不知道还要等多久——这是产品体验最大的断点。

重设计方向:① 用单一 Turn 状态机(THINKING→ACTING→WAITING→ANSWERING→DONE)作为唯一真相源,chat 与 group 共用同一套语言;② 把思考提升为永远在场的 ThinkingLayer,非 reasoner 模型用「预测步骤骨架 + 派生计划」优雅降级,不再静默;③ 思考密度改为用户偏好(隐藏/收起/预览/展开)而非写死;④ 思考与回复之间用明确的语义分隔,消除"答案凭空蹦出"的跳变。

02体验断点清单(Breakpoints)

按"用户感知到的不流畅"严重程度排序。

P0
静默空白期(最大断点)。默认模型下,用户发出复杂请求后,在 THINKING/hold 阶段只看到 ThinkingDots(三个点)。3–10 秒内完全不知道模型在规划、在调工具、还是卡死了。无预期、无进度、无取消反馈。
P0
思考的"薛定谔可见性"。同一句请求,用 deepseek-reasoner 能看到思考块,用 deepseek-v4-flash 看不到。用户无法预期界面行为,且切换模型无提示。思考成了"模型特性"而非"产品能力"。
P1
3 套思考实现、3 套状态机。①/②/③ 的收起/展开/脉冲逻辑各写各的,live 语义在 ProcessPanel 里是 parentLive 派生、在 MessageList 里是 reasoningStream 派生、在 AnswerBubble 里压根没有。后续维护改一处漏两处,已出现"完成后面泡消失"类 bug 的补丁(MessageList.tsx:198-219)。
P1
思考密度写死,用户无控制权。live 必展开、done 必收起。想复盘推理链的用户每次都要手动点开;想清爽的用户在长推理时被迫看满屏。没有全局偏好。
P2
思考↔回复边界模糊。reasoning 与 text 是两条独立流,UI 在 hold→quiet→answer 间靠词数阈值跳变,中文下推理与正式回复风格接近,用户常感觉"答案凭空蹦出来",缺少明确的语义分隔。
P2
群/chat 两套进度语言。chat 用 ProcessPanel + StreamGate;group 用 RoundtableProgressStrip / GroupRoundtable 另一套。用户跨模式时要在脑中"翻译"两套进度语义。用户说"产品架构需要重新梳理"正是此意。
P2
思考中可中断性弱。InputBar 的"停止"在 THINKING 阶段语义不清:是取消规划?还是中断生成?停止后无明确的"已停止规划"状态回执。

03目标架构:统一 Turn 状态机 + ThinkingLayer

图 1 · 单一 Turn 状态机(唯一真相源)。chat 与 group 共用同一组状态与标签。

3.1 核心组件契约

组件职责替代现状
<TurnProgress>唯一进度指示器。接收 phase / state / elapsed,渲染统一状态条。chat 与 group 共用。替代 StreamGate 散落判定 + RoundtableProgressStrip 第二套语言
<ThinkingLayer>永远在场的思考层。接收 {state, content, source, density, onToggle}。source ∈ model-reasoning | derived-plan | predicted。合并 ① ② ③ 三套 ThinkingBlock 为单一实现
<PlanStrip>把内核 TodoUpdate 全量快照渲染为"规划即思考"内容(派生 source)。当前 TodoListCard 浮窗(仅 done 展示)
TurnState (事件模型)useAgent 产出的单一对象:{phase, reasoning, plan, tools, waiting},替代散落的 reasoningStream / streamingText / isStreaming / live 多 prop。消除 MessageList/ProcessPanel/ChatArea 间 5+ 个相关 prop 拼接

3.2 ThinkingLayer 优雅降级(关键)

原则:思考是产品能力,不是模型特性。无论模型是否吐 reasoning_content,ThinkingLayer 都在场,只是内容来源不同:

  • reasoner 模型 source=model-reasoning:真实 CoT 流式进入(沿用 Rust 端已实现的 reasoning_content 解析)。
  • 非 reasoner source=derived-plan:一旦内核下发 TodoUpdate/plan,把计划渲染为思考内容——用户看到"模型在规划"。
  • 纯 hold 期 source=predicted:展示预测步骤骨架(理解需求 → 规划 → 调用工具 → 撰写回复),纯预期管理,不假装是模型原话。骨架在拿到真实内容(plan/推理)后自然替换为实质内容。

这样,默认模型下用户也永远有"可见的轨迹",静默空白期被消除。

04思考密度:改为用户偏好

把当前写死的(live 展开 / done 收起)升级为设置项 thinkingDensity,存于设置页(与主题/语言并列,属"外观/常规"语义,不要塞回"个性化")。

档位行为适用
hidden完全不渲染思考 UI(连 predicted 骨架也省)老手 / 带宽敏感
collapsed(默认)仅 header + 状态点;点击展开。对应现 done 默认行为大多数用户
peek内联显示前 2 行,展开看全部想扫一眼推理的用户
expanded始终展开完整内容(对应现 live 行为)需要信任/复盘模型的用户

默认 collapsed 保持时间线可扫读;但预测骨架(predicted)在 hold 期不受密度折叠——它是预期管理,不是推理细节,即使 collapsed 也应短暂露头(可配)。

05重设计后的流畅交互流

用户发送→ OneDesktop 身份头立刻出现→ THINKING · 预测骨架露头
→ reasoner:真实推理流入 / 非reasoner:plan 派生为思考→ ACTING · 工具在 ProcessPanel 展开
→ WAITING · 审批卡(若需)→ ANSWERING · 回复在思考层下流式生成→ DONE · 思考按密度档收起
图 2 · 单一连贯流,无静默空白、无模式跳变。思考层贯穿始终,回复在其下方以明确分隔出现。

5.1 思考 ↔ 回复的明确分隔

在 ThinkingLayer 完成(live→done)与 AnswerBubble 出现之间,插入一条轻语义分隔:思考块收起为 muted 态 + 一行"回复"标签 + 细分隔线。让"答案"是"思考的产物"而非"凭空蹦出"。分隔样式随 thinkingDensity 调节(hidden 时直接不渲染分隔)。

5.2 思考中的可中断性

  • THINKING / ACTING 阶段,InputBar 的"停止"常驻且语义明确:停止 = 取消本次规划与生成。
  • 停止后由 notice 回执"已停止规划",不再是无声 spinner 消失。
  • 可选:THINKING 阶段提供"重新规划"入口(若内核支持)。

5.3 模型选择器的思考可见性提示

InputBar 模型下拉中,reasoner 模型带 🧠 思考可见 标记;非 reasoner 模型标注"思考过程由计划/步骤替代"。用户切换即知界面差异,不再静默消失。

06开发者落地指南(迁移路径)

不要动的地方

  • Rust 端 reasoning_content 解析(deepseek.rs / llm/client.rs on_thinking)——已无条件解析,保留。
  • 工具执行可视化 ActionCard / TrivialGroup —— 已经做得好,保留。
  • 审批四态、PlanStrip 数据(内核 TodoUpdate)—— 保留。

需要收敛/新增

  • 新增 <ThinkingLayer> + <TurnProgress>,废弃 ProcessPanel/MessageList/AnswerBubble 三处 ThinkingBlock。
  • useAgent 输出单一 TurnState,替换 reasoningStream / streamingText / isStreaming / live 拼接。
  • 设置页加 thinkingDensity 偏好(与主题并列)。
  • InputBar 模型项加"思考可见"标记。
  • RoundtableProgressStrip 改为渲染同一 TurnState 的薄摘要。

6.1 建议的最小可行切片(MVP 顺序)

  1. 预测骨架 + 密度档:先解决 P0 静默空白。即使不做 reasoner 对接,非 reasoner 模型下用 predicted 骨架也立刻消除空白期。改动集中在新增 ThinkingLayer + 设置项。
  2. 三合一 ThinkingBlock:把 ①②③ 收敛到 ThinkingLayer,消除状态机分叉。
  3. TurnState 单一事件:解耦 useAgent 与渲染层,为 group 统一铺路。
  4. 群/chat 统一:RoundtableProgressStrip 接入同一状态。
  5. 模型可见性提示 + 中断回执:收尾体验闭环。
